# P0 路由与结算积压隔离

## 目标

当视频上游已完成生成但迟迟不能提供可信单任务账单时，中转站必须停止继续向该渠道分配新 v2.1 任务，同时继续查询和结算历史任务。对连续返回错误的普通文字渠道，允许通过带身份校验和备份的紧急操作停用，且不得影响健康替代渠道。

## 功能要求

- FR-001：新 v2.1 路由必须同时满足生成就绪、结算采集器就绪、人工批准、无提交故障熔断、无超时结算积压。
- FR-002：结算积压按渠道隔离；一个渠道被隔离不得影响其他渠道。
- FR-003：隔离只影响新任务；历史任务的轮询、结算和 Webhook 必须继续运行。
- FR-004：积压任务完成可信结算后，渠道应自动恢复资格，无需清理历史账本。
- FR-005：内部健康接口必须给出不含凭据的隔离原因。
- FR-006：紧急运维脚本必须在写入前备份网关 SQLite、容器配置和 NewAPI 数据库，并精确核验目标渠道身份。
- FR-007：不得用预扣价、模型广场价或余额差人工填充实际扣费。

## 验收标准

- Paisio 结算积压期间仅 Toonflow 可接新任务；Paisio 历史任务继续被领取。
- 结算积压清除后，若 Paisio 的其他资格仍满足，则自动恢复。
- Code Plan 文字渠道 39 停用且能力表同步禁用；gpt-5.5 仍有健康替代渠道。
- 两条历史 Paisio 任务以唯一账单证据结算，Webhook 已送达。
- 单元测试、全量网关测试、生产 10 轮只读核验和安全复查通过。

## 安全边界

- 不输出、提交或复制 API Key、密码、账单令牌、Webhook 密钥。
- 不创建付费视频任务。
- 不修改 CLR、视频售价或无关渠道。
