# 星途中转站对参考视频、参考音频补充协议的反馈

> 本评审稿已收口；最终执行文件为 `docs/星途AI下游视频音频v2.2最终对接说明.md`。

我们确认采用独立合同版本 `xtai-video-billing-v2.2` 对接参考视频与参考音频，但下游候选稿需要按以下意见修改后再冻结。

## 一、确认接受

1. 下游只提交稳定模型、分辨率、生成参数及规范字段 `reference_videos`、`reference_audios`，不感知具体上游渠道。
2. `generate_audio` 表示是否要求结果带声；`reference_audios` 表示输入参考音频，两者相互独立。
3. `Idempotency-Key` 必须与 `request_id` 相同；素材使用有序 SHA-256 参与幂等，短期签名 URL 不参与指纹。
4. v2.1 收到参考视频或参考音频继续在报价、冻结、建任务和调用上游前拒绝；参考素材任务只走 v2.2。
5. 查询、Webhook、结算和结果交付永久保持任务创建时的合同版本。
6. 签名 URL、用户提示词、上游凭据和上游原始错误不得进入普通日志或 Webhook。
7. 失败或受理不确定时不得换渠道重复生成；只能核对原请求和原上游任务。

## 二、建议修改

### 1. 能力目录

不要把“上游尚未联调”写成“模型不支持”。能力行拆为：

- `supported`：方舟/Seedance 官方模型是否支持；
- `available`：中转站当前是否至少有一条已验证、可结算的路由；
- `reason`：不可用原因。

官方当前确认：最多9张图片、3段视频、3段音频，图片/视频/音频可灵活组合，输出4—15秒，最高1080p。统一基础格式先支持 MP3、WAV 参考音频和 MP4 参考视频；某个上游只支持其中一部分时，只排除该路由，不删素材、不降级任务。

### 2. 计费

删除候选稿中自行增加的参考素材价格倍率。中转站统一规则为：

```text
预冻结 = 方舟对应官方输入模式价格 × 1.5
最终结算 = 本次中转任务的上游可信实际净扣费 × 1.5
```

方舟当前官方价：

| 稳定模型 | 含视频输入 | 无视频输入 |
| --- | ---: | ---: |
| 标准版 | 28元/百万tokens | 46元/百万tokens |
| Fast版 | 22元/百万tokens | 37元/百万tokens |
| Mini版 | 14元/百万tokens | 23元/百万tokens |

含 `reference_videos` 的任务使用“含视频输入”官方档；不含参考视频的任务使用“无视频输入”官方档。参考音频不另行猜测倍率。生成成功后再按上游真实净扣费 ×1.5 多退少补。

### 3. 格式与限制

下游不得把格式长期写死在客户端。中转站通过 `/v1/capabilities` 发布当时有效的 MIME、编码、数量和组合；下游根据能力目录展示和校验。新增官方格式只更新能力目录，不修改请求字段。

### 4. 上线门禁

保留三个独立开关：参考视频、参考音频、视频+音频。官方能力可标记为支持，但只有 `available=true` 的组合才能提交。正式开放前，中转站会完成真实接口样例、无费用参数验证、结算证据、Webhook 和恢复测试；付费冒烟仍需另行确认。

## 三、下游需要实现

1. 使用合同头 `X-XingTu-Contract-Version: xtai-video-billing-v2.2`。
2. 提交 `reference_videos` / `reference_audios` 完整媒体元数据与 SHA-256；保持数组顺序。
3. 提交前读取 `/v1/capabilities`，只允许 `supported=true && available=true` 的精确组合。
4. 提交前读取 `/v1/video-prices`，按中转站返回的官方输入模式价格冻结，不自行叠加倍率。
5. 本地/Base64 素材先上传下游私有 TOS，向中转站提供 HTTPS 443 短期签名 URL。
6. 回调只用于加速，原任务查询仍是权威；不得因超时换 `request_id` 重提。
7. 对用户展示中转站返回的安全具体错误，不统一改写成“视频生成失败”。

## 四、当前中转站状态

v2.2 合同识别、三开关、官方能力声明、输入模式价格说明、严格媒体元数据校验和 URL-free 幂等摘要已实现；生产付费提交仍关闭。Paisio、Toonflow、RollDek 的精确参考素材字段正在逐渠道无费用核验，核验通过后按路由开放。
